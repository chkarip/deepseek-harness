# @deepseek-ai/dsh-client-ui-activity-monitor

[English](README.md) | 中文

面向当前会话的像素风 Agent 伴侣与实时活动监控。

插件注册三个界面位置：

1. `conversation.session.header.utilities` — `ActivityHeaderPill`，紧凑的头像与吞吐徽标。点击可打开伴侣游乐场与遥测面板。
2. `conversation.input.dock` — `MascotDock`，位于输入栏上方的伴侣。它随会话状态（`idle`、`thinking`、`streaming`、`tool`、`approval`、`error`）变化，承载投喂咖啡与心情值控件，并可折叠为单行条。
3. `conversation.view` — `ActivityMonitorView`，完整标签页，包含吞吐曲线、轮次执行流转、上下文与缓存仪表盘以及外观选择器。

`/client` 入口导出插件（`apply` / `inject`）、组件、画布渲染器、遥测 Hook 与伴侣状态存储。

## 两套计数来源

本包不会凭空造出任何数字，两套来源始终分开：

- **估算值** — 曲线、头部徽标与伴侣的"投喂词元数"来自 `useLiveTelemetry`，它按流式文本的字符数近似词元数（浏览器看不到服务端的词元计数）。相应文案已标注为估算。
- **服务端上报值** — 流转视图的耗时行与仪表盘读取持久化的 `sessionStats`、`tokenUsage` 与 `contextPressure` 投影。若某投影尚未提供值，对应仪表盘直接省略，而不是取默认值：用假定的上下文窗口算出的占用率看起来像测量结果，实际却是猜测。

## 伴侣状态存储

`tamagotchiStore` 保存伴侣统计以及用户的外观、音效与折叠偏好，并镜像到 `localStorage` 的 `dsh:activity-monitor:tamagotchi` 键下。它刻意是模块级单例，位于插件生命周期之外：其中每个值都是按浏览器保存的用户偏好，必须在插件卸载与组件重挂载后继续存在，正如支撑它的那条存储记录一样。写入被合并为最多每两秒一次的存储写，外加 `pagehide` 时的一次刷写，这样流式词元增量就不会在每一帧都触发同步序列化。

音效默认关闭。开启后，仅由伴侣区域（若三个界面都发声，就会各响一次）在轮次完成时播放一次 8-bit 提示音。

## 模型体验

无，因为这里的每个界面都只渲染浏览器端状态；它注册的内容都不会进入模型请求。

#### KV 缓存影响

无；本包既不组装也不发送服务端请求。

## 已知局限与延后工作

- **按浏览器持久化** — 伴侣统计与偏好保存在单个浏览器的 `localStorage` 中。它们不会跟随用户到其他浏览器或设备，也不属于会话日志。
- **仅有估算吞吐** — 实时曲线无法锚定到服务端，因为从流式文本无法观测分词。流转视图中服务端上报的解码速率是整个会话的，而非实时值。
